### 教学过程 1

今天的 `07_information_extraction.py` 最后执行的是：

```python
print(response.choices[0].message.content)
```

这只能把模型返回的文字显示出来。假设模型返回：

````text
```json
{"日期":"2025-06-06","股票名称":"黑马程序员A股","开盘价":"200人民币","收盘价":"206人民币"}
```
````

需要依次检查：

1. **语法解析**：最外层的 Markdown 代码围栏不是 JSON 语法，直接传给 `json.loads()` 会失败。程序应取得纯 JSON 文本并捕获 `JSONDecodeError`。不能因为人眼看起来像 JSON，就认为 Python 已经得到字典。
2. **字段/schema**：即使成功解析成字典，也要检查是否恰好具有业务需要的字段。示例缺少“成交量”，因此不能悄悄写入一个本应完整的数据库记录；应按业务约定拒绝、标记缺失，或使用明确的缺失值。
3. **类型与业务约束**：字段存在也不代表值有效。例如数据库可能要求成交量是整数，而不是字符串；日期必须是合法日期；价格不能是任意文字或负数。需要把值转换成规定类型，并验证取值范围或格式。
4. **失败处理**：任何一步失败，都不应继续正常写库。程序应记录错误和原始响应，并选择停止写入、返回明确错误、有限次数重试，或转人工确认。不能用猜测的数据掩盖失败。
5. **few-shot 的边界**：示例能告诉模型期望的字段名、格式和缺失值写法，因此能提高它按格式回答的概率；但语言模型的输出具有不确定性，few-shot 不能保证每一次都合法、完整、类型正确，所以程序校验仍然不可省略。

可以把整个过程理解成：

```text
模型文本 → JSON 解析 → 字段检查 → 类型/业务检查 → 成功后才写数据库
              任一步失败 → 不写入，并明确处理错误
```
