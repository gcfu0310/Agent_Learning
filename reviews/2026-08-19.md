## 知识检查与教学

### 知识点 1：Runnable 字典分支与最小检索链类型流

#### 问题

解释以下链在 `chain.invoke("怎么减肥？")` 时，同一个字符串经过哪些分支和组件、每一步的输入输出类型，以及为什么 `input` 分支需要 `RunnablePassthrough()`，而 `context` 分支不能直接原样传递。

```python
chain = {
    "input": RunnablePassthrough(),
    "context": retriever | format_func
} | Chat_Prompt | print_Prompt | llm_model | str_parser
```

#### 我的原始回答

> 当 chain.invoke("怎么减肥？") 执行时，字符串"怎么减肥？"根据RunnablePassthrough传送给“input”，同时也给了retriever，retriever进行向量检索，输出的是[Document,Document....]类型的检索结果，接着输入给format_func，输出成字符串格式的检索结果，接着完整的字典格式的内容传给ChatPrompt，输出PromptValue格式的prompt，经过print_Pormpt打印字符串，输出和输入一样不变，接着传给llm_model，输出AIMessage格式的最终回答，最后通过str_parser将最终答案转换成字符串格式
> 因为根据invoke传给的是链中的第一个组件，外部看第一个组件是字典，字典内的第一个组件是retriever,所以input默认会给它，而“input”需要RunnablePassthrough()

#### 提示 / 教学过程

原始回答正确说明了主要类型流，但把 Runnable 字典理解成了有先后顺序的组件。给出的方向性提示是：字典的每个 value 都会收到同一份原始输入；每个 value 决定如何处理该输入，键名只是汇总分支结果时的输出字段名。随后要求说明删除 `input` 分支后的字典形状和报错原因。

#### 我的重新回答

> 会变成{“context”:检索内容},因为Chat_Prompt中有两个关键字,字典中缺少一个关键字，所以会报错

#### 评价

能够独立解释 `str → list[Document] → str` 的检索分支以及 `dict → PromptValue → AIMessage → str` 的后续类型流。经一次方向性提示后，正确补全了 Runnable 字典的并行映射机制，并知道删除 passthrough 分支会使 Prompt 输入只剩 `context`。更准确地说，缺少的是模板必需变量 `input`，错误发生在 `ChatPromptTemplate` 格式化阶段。

#### 正确理解

Runnable 字典不是按键顺序依次执行。两个 value 都接收原始 query：`RunnablePassthrough()` 原样输出 query 并保存为 `input`；Retriever 把 query 转成 `list[Document]`，`format_func` 再转成字符串并保存为 `context`。两个结果汇总成 `{"input": query, "context": text}` 后交给 Prompt。若删除 passthrough 分支，Prompt 只收到 `context`，因缺少必需变量 `input` 而在模板格式化阶段失败。
